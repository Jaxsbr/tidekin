## Architecture brief

`game.js` is the strongest boundary: dependency-free state/rules and steering, deterministic advancement, action failures that preserve state, immutable catalogs, presentation context, and atomic parsing/migration. `main.js` coordinates menus, storage, focus/input, audio, HUD, and frame scheduling. `scene.js` owns Three.js resources, asset-node bindings, effects, and camera, and consumes authoritative state. `index.html` supplies the semantic UI shell and dialogs.

The earlier steering isolation concern is resolved. [src/game.js:73](/Users/jacobusbrink/Jaxs/projects/tidekin/src/game.js:73) now owns normalized movement, dive speed, shoal slowdown, delta validation, and bounds. The main loop calls steering, then domain advancement, then rendering ([src/main.js:596](/Users/jacobusbrink/Jaxs/projects/tidekin/src/main.js:596)). The renderer probe confirms that input and a nonzero delta do not mutate authoritative state. The steering regressions cover diagonal distance, diving speed, bounds, invalid inputs, invalid/zero deltas, and escape from low-water shoals. The full-chain test still uses direct position assignment as a fast route fixture; it should not be described as a real-input browser playtest.

Possible duplicated-rules smell: `main.js` independently computes gather blocks, recipe reasons, travel gates, and regional checks even though `getContext()` supplies permissions. Current thresholds are aligned, so this is a maintenance risk, not a separate confirmed defect. Prefer authoritative context plus presentation mapping rather than maintaining two rule sets. Persisted speed duplicates the selected rig's data but is checked for exact consistency; no rig exploit was found. The domain header now documents variable oxygen and authoritative steering correctly.
